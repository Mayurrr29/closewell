# Deploy for free: Vercel (web) + Render (API) + MongoDB Atlas (database)

```
visitor ──► Vercel (web app, always on)
              │  /api/*  and  /widget.js  are forwarded
              ▼
           Render free web service (API + job worker)
              │
              ▼
           MongoDB Atlas free cluster
```

The browser only ever talks to the Vercel domain, so the sign-in cookie stays first-party and no CORS setup is needed.

**Free-tier trade-offs (checked October 2026; confirm on each provider's pricing page):**

- **Render free:** 512 MB RAM, 0.1 CPU and 750 instance hours a month. It sleeps after 15 minutes without traffic, and the first request after that takes about a minute. 5 GB outbound bandwidth a month.
- **While the API sleeps**, background jobs (document indexing, approved actions, expiring approvals) wait. They are stored in the database and run as soon as it wakes. Nothing is lost.
- **Atlas M0:** 512 MB storage, shared CPU.

Do the steps in this order: the database first, then the API, then the web app, then link them.

## 1. Database: MongoDB Atlas

1. Sign up at https://www.mongodb.com/cloud/atlas and create a **free (M0)** cluster. Pick a region near Render's Singapore region, for example **Mumbai** or **Singapore**.
2. **Database Access** → add a database user with a long random password (letters and numbers only, so it needs no URL-encoding).
3. **Network Access** → add `0.0.0.0/0`. Render's free instances have no fixed outbound IP; the long password is what protects the database.
4. **Connect → Drivers** → copy the connection string and add a database name before the `?`:
   ```
   mongodb+srv://USER:PASSWORD@cluster0.xxxxx.mongodb.net/salesbot?retryWrites=true&w=majority
   ```

## 2. API: Render

1. Sign in at https://render.com with GitHub.
2. **New → Blueprint** → choose the `Mayurrr29/closewell` repo. Render reads `render.yaml` and proposes one free web service, `salesbot-ai-api`.
3. Fill the values it asks for:

   | Variable | Value |
   |---|---|
   | `MONGODB_URI` | the Atlas string from step 1 |
   | `APP_ORIGIN` | `https://PLACEHOLDER.vercel.app` (you fix it in step 4) |
   | `API_PUBLIC_URL` | same as `APP_ORIGIN` |
   | `OPENAI_API_KEY`, `EMAIL_FROM`, `SMTP_*` | leave empty for now |

   `JWT_ACCESS_SECRET` and `ENCRYPTION_KEY` are generated by Render automatically. Don't change them later: changing them signs everyone out and makes stored credentials unreadable.
4. **Apply.** The first build takes a few minutes. Then open the service and note its URL.
   - If the URL is **not** `https://salesbot-ai-api.onrender.com` (Render adds a suffix when a name is taken), change both URLs in `apps/web/vercel.json` to yours and push.
5. Check `https://YOUR-RENDER-URL/api/health`. It should return `"status":"ok","db":"ok"`.

## 3. Web app: Vercel

1. Sign in at https://vercel.com with GitHub → **Add New → Project** → import `Mayurrr29/closewell`.
2. Set **Root Directory** to `apps/web`. Leave the rest: `apps/web/vercel.json` already sets the install command, build command, output folder, the API forwarding and security headers.
3. **Deploy**, then note the URL, for example `https://closewell-xyz.vercel.app`. A custom domain can be added later under Settings → Domains.

## 4. Link them

1. In Render → `salesbot-ai-api` → **Environment**, set `APP_ORIGIN` and `API_PUBLIC_URL` to the Vercel URL (no trailing slash). Save; Render redeploys.
2. Open `https://YOUR-VERCEL-URL/api/health`:
   - `"db":"ok"` means Vercel → Render → Atlas works.
   - `clientIp` should start with your own network's address. If it shows something else, tell me and I'll adjust `TRUST_PROXY`.
3. Open the Vercel URL and create your account.

## 5. Email (needed to publish an agent)

Publishing an agent and inviting teammates both need a verified email, and **with `EMAIL_MODE=mock` no email is sent**. The dev mailbox is disabled in production. Either:

- **Connect SMTP** (recommended): in Render set `EMAIL_MODE=smtp`, `SMTP_HOST`, `SMTP_PORT` (usually 587), `SMTP_USER`, `SMTP_PASS` and `EMAIL_FROM`. Any SMTP provider works; several (for example Brevo, Resend, Mailgun) have free tiers.
- **Or, for your own test account only:** in Atlas → Browse Collections → `users` → your document, set `emailVerifiedAt` to the current date.

## 6. Real AI (optional)

In Render set `AI_PROVIDER=openai` and `OPENAI_API_KEY`. Until then replies come from the labelled mock AI. The OpenAI adapter has not yet been run against the live API, so try a few test conversations in the agent's **Test** tab first.

## 7. Put the chat on a website

In the app go to **Website chat**, add your site's domain, turn the chat on, publish the agent and paste the snippet. The snippet loads `https://YOUR-VERCEL-URL/widget.js`.

## Updating

Every push to `main` redeploys both automatically: Render rebuilds only when backend files change, and Vercel rebuilds on every push.

## Troubleshooting

| Problem | Fix |
|---|---|
| Render build fails on TypeScript or esbuild | The build command must keep `--include=dev` (Render sets `NODE_ENV=production`, which would skip build tools). |
| `/api/health` on Vercel returns 404 or an HTML page | Wrong Render URL in `apps/web/vercel.json`, or the Vercel root directory is not `apps/web`. |
| `"db":"error"` or the service crash-loops | Check `MONGODB_URI`, the Atlas user password, and that `0.0.0.0/0` is in Network Access. |
| The first load is slow | The free Render service was asleep. It takes about a minute to wake. |
| Signed out after every redeploy | `JWT_ACCESS_SECRET` changed. Keep the generated value. |
| Can't publish the agent | Verify your email (step 5). |
